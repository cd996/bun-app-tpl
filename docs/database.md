# Database

The API uses SQLite through Drizzle ORM. Table definitions live in each module's own `apps/api/src/modules/<name>/schema.ts`; `apps/api/src/db/schema.ts` is a re-export aggregator only and contains no table definitions.

## Conventions

| Topic | Current behavior |
|---|---|
| Database | SQLite |
| ORM | Drizzle ORM |
| Time fields | ISO 8601 strings |
| Booleans | SQLite integer booleans |
| Business IDs | Text IDs generated by service code |

## Tables

### `users`

Local account records created or updated from OAuth userinfo.

Key fields: `id`, `oauth_sub`, `username`, `name`, `email`, `avatar`, `role`, `status`, `last_login_at`, `created_at`, `updated_at`.

Indexes enforce unique OAuth subject, username, and email.

### `groups`

Account groups used for membership and policy subjects.

Key fields: `id`, `name`, `description`, `created_at`, `updated_at`.

### `sessions`

Server-side OAuth sessions.

Key fields: `id`, `user_id`, `access_token`, `refresh_token`, `expires_at`, `created_at`, `updated_at`.

### `pkce_challenges`

Temporary OAuth PKCE state.

Key fields: `state`, `code_verifier`, `redirect_uri`, `expires_at`.

### `audit_events`

Immutable audit log records.

Key fields: `id`, `actor_id`, `actor_name`, `action`, `resource_type`, `resource_id`, `resource_name`, `detail`, `ip`, `user_agent`, `result`, `created_at`.

### `settings`

Runtime settings stored by key.

Key fields: `key`, `value`, `updated_by`, `updated_at`.

### `user_preferences`

Per-user preference storage.

Primary key: `(user_id, key)`.

### `todos`

Todo records.

Key fields: `id`, `title`, `description`, `status`, `priority`, `creator_id`, `assignee_id`, `due_date`, `created_at`, `updated_at`.

### `todo_attachments`

Files attached to todos.

Key fields: `id`, `todo_id`, `filename`, `filepath`, `mimetype`, `size`, `uploaded_by`, `created_at`.

### `todo_comments`

Comments attached to todos.

Key fields: `id`, `todo_id`, `author_id`, `content`, `created_at`, `updated_at`.

### `document_folders`

Folders for documents.

Key fields: `id`, `name`, `creator_id`, `created_at`, `updated_at`.

### `documents`

Document records.

Key fields: `id`, `title`, `content`, `tags`, `folder_id`, `creator_id`, `created_at`, `updated_at`.

### `document_attachments`

Files attached to documents.

Key fields: `id`, `document_id`, `filename`, `filepath`, `mimetype`, `size`, `uploaded_by`, `created_at`.

### `document_comments`

Comments attached to documents.

Key fields: `id`, `document_id`, `author_id`, `content`, `created_at`, `updated_at`.

### `document_shares`

User and group shares for documents.

Key fields: `id`, `document_id`, `target_type`, `target_id`, `permission`, `created_at`.

### `user_totp_devices`

TOTP devices for users.

Key fields: `id`, `user_id`, `name`, `secret`, `verified`, `created_at`.

### `totp_challenges`

Temporary login-time TOTP challenges.

Key fields: `id`, `user_id`, `access_token`, `refresh_token`, `expires_in`, `redirect_uri`, `expires_at`.

### `relation_tuples`

Zanzibar-style relation tuples.

Key fields: `id`, `namespace`, `object_id`, `relation`, `subject_namespace`, `subject_id`, `subject_relation`, `created_by`, `created_at`.

The application also checks duplicate tuples in service code because SQLite treats `NULL` values as distinct in unique constraints.

## Current Schema Scope

The current schema does not include application inventory, domains, hosts, Headscale devices, DNS zones, or API keys.
