# Rebranding

The template is designed so that almost all identity (HTML title, URL prefix, backup filenames, TOTP issuer, etc.) flows from two env vars set in `.env`:

```bash
APP_NAME=myapp          # slug: /^[a-z][a-z0-9-]*$/
APP_DISPLAY_NAME=My App # human-readable display name
```

If you set those before running `bun run dev` / `bun run build` / `bun run compile`, the bulk of the rebranding is done.

## What flows from `APP_NAME`

| Surface | Where |
|---|---|
| Default `BASE_PATH` (`/<APP_NAME>`) | `apps/api/src/config.ts`, `apps/web/vite.config.ts` |
| Static-asset URL prefix in compiled binary | `scripts/compile.ts` |
| Backup download filename (`<APP_NAME>-backup-*.json`) | `apps/api/src/modules/backup/export.routes.ts`, `apps/web/src/app/routes/_app/admin/settings.lazy.tsx` |
| Master-key download filename | `apps/web/src/app/routes/setup.tsx` |
| Unlock-challenge `sessionStorage` key | `apps/web/src/app/routes/unlock.tsx` |
| `nsl` dev URL routing | `apps/api/package.json`, `apps/web/package.json` |

## What flows from `APP_DISPLAY_NAME`

| Surface | Where |
|---|---|
| HTML `<title>` | `apps/web/index.html` (`%VITE_APP_DISPLAY_NAME%`) |
| Document title shown in tabs and pages | `apps/web/src/shared/hooks/use-page-title.ts` |
| Login screen heading | `apps/web/src/app/routes/login.tsx` |
| TOTP issuer (shown in authenticator apps) | `apps/api/src/modules/account/users/totp.service.ts` |
| Default SMTP "from name" placeholder | `apps/web/src/app/routes/_app/admin/settings.lazy.tsx` |

The frontend reads both via the single import `@/shared/lib/branding` (`APP_NAME`, `APP_DISPLAY_NAME`); the API reads them via `Bun.env.APP_NAME` / `Bun.env.APP_DISPLAY_NAME` and the validated `Config`.

## Manual rebranding (the rest)

These items are intentionally not env-driven; edit them once when you fork:

| Item | File |
|---|---|
| Logo SVG and brand-mark colors | `apps/web/src/shared/components/logo.tsx`, `apps/web/public/logo.svg` |
| Favicon | `apps/web/public/logo.svg` |
| Package scope `@app/*` | `package.json`, `apps/*/package.json`, `packages/*/package.json`, `bun.lock` (regenerated by `bun install`) |
| Repository name and remote | git config |
| Container base image | `Dockerfile` (default `zzci/ubase`) |
| OAuth client id/secret in your IdP | `.env` (`OAUTH_*`) |

## Verification script

After rebranding, run (substitute `<OLD_NAME>` with your previous `APP_NAME` and `<OLD_DISPLAY>` with your previous `APP_DISPLAY_NAME`):

```bash
rg -i \
  --glob '!node_modules' --glob '!dist' --glob '!.git' \
  -e '<OLD_NAME>' -e '<OLD_DISPLAY>' \
  apps/ packages/ scripts/
```

`<OLD_NAME>` and `<OLD_DISPLAY>` are placeholders — replace them with the actual literals before running. Anything that comes back is something the template missed.

## Reverse-proxy mounting

`BASE_PATH` lets you serve under any prefix:

```bash
APP_NAME=myapp              # → BASE_PATH defaults to /myapp
# or override explicitly:
BASE_PATH=/tools/myapp
```

The reverse proxy must mount the app at the same prefix and forward the `Host` header (or set `ACCESS_URL` to your public URL — required in production).
