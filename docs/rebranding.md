# Rebranding

The template is designed so that almost all identity (HTML title, URL prefix, backup filenames, TOTP issuer, etc.) flows from two env vars set in `.env`:

```bash
APP_NAME=myapp          # slug: /^[a-z][a-z0-9-]*$/
APP_DISPLAY_NAME=My App # human-readable display name
```

If you set those before running `bun run dev` / `bun run build` / `bun run compile`, the bulk of the rebranding is done.

## One-shot helper

For a freshly forked repo, run the bundled rebrand helper to update every
manifest in one go (env defaults, every `package.json`'s `homepage` /
`repository.url`, and optionally the `@app/*` package scope):

```bash
bun run rebrand \
  --name myapp \
  --display "My App" \
  --scope myorg \
  --repo https://github.com/myorg/myapp
# Add --dry-run first to preview without writing.
```

The script prints the manual follow-up it can't do safely (git remote
update, logo replacement, lockfile regen). Re-running with different
arguments is idempotent.

## What flows from `APP_NAME`

| Surface | Where |
|---|---|
| Static-asset URL prefix in compiled binary | `scripts/compile.ts` |
| Backup download filename (`<APP_NAME>-backup-*.json`) | `apps/api/src/modules/backup/export.routes.ts`, `apps/web/src/app/routes/_app/admin/settings.lazy.tsx` |
| Master-key download filename | `apps/web/src/app/routes/setup.tsx` |
| Unlock-challenge `sessionStorage` key | `apps/web/src/app/routes/unlock.tsx` |
| `nsl` dev URL routing | `apps/api/package.json`, `apps/web/package.json` |

## What flows from `APP_DISPLAY_NAME`

| Surface | Where |
|---|---|
| HTML `<title>` | `apps/web/index.html` (`%VITE_APP_DISPLAY_NAME%`) |
| Document title shown in tabs and pages | `apps/web/src/shared/hooks/use-page-title.ts` |
| Login screen heading | `apps/web/src/app/routes/login.tsx` |
| TOTP issuer (shown in authenticator apps) | `apps/api/src/modules/account/users/totp.service.ts` |
| Default SMTP "from name" placeholder | `apps/web/src/app/routes/_app/admin/settings.lazy.tsx` |

The frontend reads both via the single import `@/shared/lib/branding` (`APP_NAME`, `APP_DISPLAY_NAME`); the API reads them via `Bun.env.APP_NAME` / `Bun.env.APP_DISPLAY_NAME` and the validated `Config`.

## Manual rebranding (the rest)

These items are intentionally not env-driven; edit them once when you fork:

| Item | File |
|---|---|
| Logo SVG and brand-mark colors | `apps/web/src/shared/components/logo.tsx`, `apps/web/public/logo.svg` |
| Favicon | `apps/web/public/logo.svg` |
| HTML meta description / theme-color (for public-facing deploys) | `apps/web/index.html` |
| Package scope `@app/*` | `package.json`, `apps/*/package.json`, `packages/*/package.json`, `bun.lock` (regenerated by `bun install`). Use `bun run rebrand --scope <yourorg>` to rewrite in one pass. |
| `homepage` / `repository.url` in every `package.json` | Top-level + `apps/*` + `packages/*`. Use `bun run rebrand --repo <git-url>`. |
| `description` in top-level `package.json` | `bun run rebrand --description "..."`. |
| Repository name and remote | `git remote set-url origin <your-fork-url>` |
| Container base image | `Dockerfile` (default `debian:stable-slim`; override via `--build-arg RUNTIME_BASE=...`) |
| Container source-revision label | `--build-arg BUILD_COMMIT=$(git rev-parse --short HEAD)` (`.git` is excluded from the build context, so the build cannot resolve it on its own) |
| OAuth client id/secret in your IdP | `.env` (`OAUTH_*`) |

### Reference compose stack (`examples/compose/`)

The bundled docker-compose stack ships with **demo credentials** that
**must** be rotated before any non-local deploy:

| Surface | Default | Action |
|---|---|---|
| `OAUTH_CLIENT_ID` | `app` | Whatever your IdP registers. |
| `OAUTH_CLIENT_SECRET` | `app-secret` | Generate a real secret; **production refuses to boot with this value**. |
| `DEFAULT_ADMIN` | `admin@example.com` | Your real first-admin email. |
| Dex static users | `admin@example.com` / `user@example.com` (bcrypt of `"admin"`) | Replace `staticPasswords` in `dex.yaml` with your IdP connectors. |
| Dex image tag | `dexidp/dex:v2.43.1` (pinned) | Bump deliberately when the upstream changelog is vetted. |
| App image name | `${APP_NAME:-app}:local` | The image you actually publish. |

## Verification script

After rebranding, run (substitute `<OLD_NAME>` with your previous `APP_NAME` and `<OLD_DISPLAY>` with your previous `APP_DISPLAY_NAME`):

```bash
rg -i \
  --glob '!node_modules' --glob '!dist' --glob '!.git' \
  -e '<OLD_NAME>' -e '<OLD_DISPLAY>' \
  apps/ packages/ scripts/
```

`<OLD_NAME>` and `<OLD_DISPLAY>` are placeholders — replace them with the actual literals before running. Anything that comes back is something the template missed.

## Reverse-proxy mounting

`BASE_PATH` is unset by default — the app mounts at root (`/`). Set it to serve under a URL prefix:

```bash
BASE_PATH=/tools/myapp
```

`BASE_PATH` accepts `myapp`, `/myapp`, or `/myapp/`; all three normalise to `/myapp`. The reverse proxy must mount the app at the same prefix and forward the `Host` header (or set `ACCESS_URL` to your public URL — required in production).
